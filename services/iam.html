🔐 AWS IAM / AWS Organizations CLF

AWS IAM（Identity and Access Management）は、「誰が」「どのリソースに」「どの操作を実行できるか」を管理するサービスです。 CLF試験で最も重要なサービスの一つで、ほぼ全てのセキュリティ問題に関係します。

AWSアカウントのユーザー種類

👑 AWSアカウントルートユーザー

AWSアカウント作成時に使用したメールアドレスで認証するユーザー。全リソースへの全権限を持ちます。

  • 日常的な運用には使用しないことが強く推奨
  • ルートユーザーでしかできない操作（アカウントの削除、サポートプランの変更等）のみ使用
  • MFA（多要素認証）の有効化が必須
👤 IAMユーザー

IAMで作成した個別ユーザー。ポリシーをアタッチすることで特定の操作のみ許可できます。

  • 日常の運用・開発はIAMユーザーで行う
  • ユーザー名＋パスワード or アクセスキーで認証
  • 最小権限の原則：必要最低限のアクセス権のみ付与

IAMの主要コンポーネント

👤 IAMユーザー（User）

AWSサービスにアクセスする個人またはアプリケーションを表す。パスワードまたはアクセスキーで認証。

👥 IAMグループ（Group）

IAMユーザーのコレクション。グループにポリシーをアタッチすれば、グループ内の全ユーザーに同じ権限が付与される。

🎭 IAMロール（Role）

AWSサービスや外部ユーザーに一時的な権限を付与する仕組み。EC2インスタンスやLambdaにロールをアタッチして権限を付与する用途が多い。

📜 IAMポリシー（Policy）

どのAWSリソースに対してどの操作（許可/拒否）ができるかをJSONで定義したもの。ユーザー・グループ・ロールにアタッチして使用。

IAMポリシーの種類

ポリシー種類説明アタッチ先
IDベースポリシーIAMユーザー・グループ・ロールにアタッチ。「このIDが何を実行できるか」を定義ユーザー/グループ/ロール
リソースベースポリシーS3バケットポリシーなど。「このリソースに誰がアクセスできるか」を定義S3・SQS・Lambda等
AWS管理ポリシーAWSが事前に定義したポリシー（例：AmazonS3ReadOnlyAccess）—
カスタマー管理ポリシーユーザーが独自に作成したポリシー—
明示的な拒否 > 明示的な許可 > 暗黙の拒否
IAMポリシーの評価順序：Deny（明示的拒否）は常に最優先。デフォルトでは全て「暗黙の拒否」。

MFA（多要素認証）

MFA（Multi-Factor Authentication）とは、パスワードに加えてもう一つの認証要素を要求することで、セキュリティを強化する仕組みです。AWSではルートユーザーと重要なIAMユーザーへのMFA有効化が強く推奨されています。

IAM Access Analyzer

意図せず外部に公開されているリソース（S3バケット、IAMロールなど）を自動検出するサービスです。セキュリティリスクを早期発見・修正できます。

IAMユーザーの認証情報

🖥 コンソールアクセス

ユーザー名＋パスワードでAWS管理コンソールにログイン。MFAも組み合わせることが推奨。

🔑 プログラムアクセス

アクセスキーIDとシークレットアクセスキーのペアでCLI・SDK・APIからアクセス。シークレットキーは作成時のみ表示される。

📊 認証情報レポート

全IAMユーザーの認証情報の使用状況（最終ログイン日、MFAの状態、パスワードの最終変更日等）を確認できるレポート機能。

Microsoft Active Directory との ID 連携

AWS Directory Service や AWS IAM Identity Center を使うことで、オンプレミスのActive Directoryユーザーアカウントを使ってAWSにシングルサインオン（SSO）できます。IAMユーザーを個別に作成・管理せずに既存のADアカウントを活用できます。

AWS Organizations — 複数アカウント管理

AWS Organizationsは、複数のAWSアカウントを一元管理するサービスです。企業では開発・ステージング・本番など複数のAWSアカウントを使い分けることが多く、それらを組織として管理できます。

🏢 組織構造

マスターアカウント（管理アカウント）が組織全体を管理。OU（組織単位）でアカウントをグループ化できます。

🔒 SCP（サービスコントロールポリシー）

OU・アカウントに対して適用できる権限の上限を定義するポリシー。SCPで拒否された操作はIAMポリシーで許可されていても実行不可。

💰 一括請求（Consolidated Billing）

組織内の全アカウントの請求をマスターアカウントで一括管理。使用量の合算によりボリューム割引が受けられることもある。

🔶 試験のポイント（CLF・SAA 最頻出）
  • ルートユーザーは日常使用禁止。必ずMFAを有効化
  • 最小権限の原則：必要な権限のみ付与する
  • IAMロールはEC2・Lambdaなどのサービスに権限を付与する手段（アクセスキー不要）
  • 明示的な拒否（Deny）は常に最優先
  • IAMグループにポリシーをアタッチすれば、グループ内全ユーザーに適用される
  • SCP（Organizations）はIAMポリシーより上位：SCPで拒否されたらIAMで許可しても実行不可
  • IAMはグローバルサービス（リージョンを選ばない）
  • 「EC2からS3にアクセスしたい → EC2にIAMロールをアタッチ」（アクセスキーを使わない）
