🖥 Amazon EC2 CLF

Amazon EC2（Elastic Compute Cloud）は、AWSが提供する仮想サーバー（仮想マシン）サービスです。 IaaSの代表的サービスで、数分以内にサーバーを起動でき、使用量に応じた課金が適用されます。 EC2はAWSの根幹をなすサービスで、CLF・SAA両方の試験で頻出です。

EC2インスタンスの起動設定

🖼 AMI（Amazon Machine Image）

EC2インスタンスのOS・アプリケーション・設定を含むテンプレート。インスタンスの「元型」。

  • AWS提供AMI（Amazon Linux・Windows Server等）
  • AWS Marketplace AMI（サードパーティ製品）
  • カスタムAMI（自分で作成・カスタマイズ済み）
⚙️ インスタンスタイプ

CPUコア数・メモリ量・ネットワーク帯域などのスペックを定義するもの。用途に応じて選択します。

🔑 キーペア

EC2インスタンスへのSSH接続（Linuxの場合）またはRDP接続（Windowsの場合）に使用する公開鍵・秘密鍵のペア。秘密鍵（.pem）はダウンロード後AWSには保存されないので大切に保管する。

🌐 ネットワーク設定

VPCとサブネットを選択。セキュリティグループでインバウンド/アウトバウンドのトラフィックを制御します。

インスタンスタイプの種類

ファミリー特徴用途例代表インスタンス
汎用（M/T系）CPU・メモリ・ネットワークのバランス型Webサーバー・小規模DBt3.micro, m6i.large
コンピューティング最適化（C系）高性能CPU比率バッチ処理・ゲームサーバーc6i.large
メモリ最適化（R/X系）大量メモリインメモリDB・大規模キャッシュr6i.large
ストレージ最適化（I/D系）高速NVMe SSDNoSQL DB・データウェアハウスi3.large
高速コンピューティング（P/G系）GPU搭載機械学習・グラフィック処理p3.2xlarge

ストレージの設定

💿 EBSボリューム（推奨）

インスタンスとは独立したネットワーク接続ストレージ。インスタンスを停止・削除してもデータを保持できる。スナップショットでバックアップ可能。

💾 インスタンスストア（一時ディスク）

物理ホストに直接接続された一時ストレージ。インスタンス停止・終了でデータは消える。高速だが永続化不可。

🧭 どちらを選ぶ？ — EC2 vs Lambda

🖥 Amazon EC2

OSレベルの設定・管理が必要
長時間実行するプロセスが必要（15分超）
既存のアプリをリフト&シフト移行
状態を保持するアプリケーション
例：Webサーバー、DBサーバー
IaaS サーバー管理 長時間実行
VS

⚡ AWS Lambda

サーバー管理不要
イベント駆動・短時間処理（最大15分）
アイドル時間のコスト削減
自動スケーリングが必要
例：画像処理、API処理、定期実行
サーバーレス 従量課金 イベント駆動
🔶 試験のポイント（CLF・SAA 頻出）
  • EC2はIaaS：OSパッチ適用・セキュリティグループ管理はユーザー責任
  • AMI：EC2インスタンスの「テンプレート」（OS・設定込み）
  • インスタンスタイプ：汎用（M/T）・コンピューティング最適化（C）・メモリ最適化（R）を区別
  • キーペアの秘密鍵はダウンロード後AWSに保存されない
  • 停止 vs 終了：停止はEBSデータ保持・再起動可、終了はデータ削除・課金停止
  • インスタンスストアはインスタンス停止でデータ消失（一時ストレージ）
  • EBSはインスタンスとは独立したストレージ（停止してもデータ保持）
