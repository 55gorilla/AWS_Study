📁 Amazon EFS SAA

Amazon EFS（Elastic File System）は、複数のEC2インスタンスから同時にアクセスできるNFSファイルストレージです。 EBSが1つのEC2インスタンスにしかアタッチできないのに対し、EFSは複数インスタンスで共有できます。 また、使用量に応じてストレージ容量が自動的に拡張・縮小します。

Amazon EFS の概要

主な特徴

🔗 複数EC2インスタンスで共有

NFS（Network File System）プロトコルを使用。複数のEC2インスタンスから同時にマウント・アクセス可能。同一AZ内でも、複数AZにまたがることも可能。

📊 自動スケーリング

ファイルの追加・削除に応じてストレージ容量が自動的に増減する。EBSのように事前に容量を確保する必要がない。

🏢 高可用性・耐久性

データは複数のAZに自動的にレプリケートされる（Standardクラス）。単一AZ障害が発生してもデータにアクセスできる。

💰 ストレージクラスとライフサイクル

頻繁にアクセスしないファイルを低コストのInfrequent Accessクラスに自動移行できる。ライフサイクルポリシーで移行の条件（日数）を設定。

ストレージクラス

ストレージクラス 説明 コスト 用途
EFS Standard 複数AZにレプリケート。高可用性。 高め 頻繁にアクセスするデータ
EFS Standard-IA 複数AZにレプリケート。アクセス時に追加料金。 低い（ストレージ料金） 頻繁にアクセスしないデータ
EFS One Zone 単一AZのみ。 低い 開発環境・バックアップ
EFS One Zone-IA 単一AZ・低頻度アクセス。 最も低い 開発環境の低頻度データ

EBS vs EFS 比較

比較項目 EBS（Elastic Block Store） EFS（Elastic File System）
ストレージ種別 ブロックストレージ ファイルストレージ（NFS）
同時接続 1インスタンスのみ（Multi-Attach対応のものは除く） 複数インスタンスから同時アクセス可
AZ 単一AZにのみ存在 複数AZにまたがる（Standardクラス）
容量管理 事前に容量を確保・手動拡張 自動でスケーリング（ペタバイト規模まで）
プロトコル iSCSI / ブロックデバイス NFS v4.1 / v4.0
OS対応 Linux / Windows Linux のみ
主な用途 OS起動ドライブ、データベースディスク 共有コンテンツリポジトリ、機械学習データセット、Webファーム
🔶 試験のポイント（SAA 頻出）
  • 「複数のEC2インスタンスで同じファイルを共有したい → EFS」
  • EBSは1インスタンス専用（原則）、EFSは複数インスタンスで共有可能
  • EFSはLinuxのみ対応（WindowsにはEFSは使えない）
  • EFSは容量が自動でスケーリング — 事前に容量を確保する必要なし
  • EFS Standard-IAライフサイクルポリシーでコスト最適化可能
  • 「Webアプリの静的コンテンツを複数EC2で共有 → EFS」
