🐳 Amazon ECS / AWS Fargate / Amazon EKS CLF SAA

コンテナとは、アプリケーションとその実行環境（ライブラリ・設定等）を一つのパッケージにまとめた軽量で移植可能な形式です。 AWSはコンテナを実行・管理するための複数のサービスを提供しています。

コンテナとコンテナオーケストレーション

📦 コンテナとは

アプリケーションコードと実行に必要なライブラリ・設定を一つのイメージ（テンプレート）にまとめたもの。どの環境でも同じ動作を保証できます。VMより軽量で起動が速い。

🎛 コンテナオーケストレーション

多数のコンテナの起動・停止・スケーリング・配置を自動管理する仕組み。手動管理では大規模に対応できないため自動化が必要。

Amazon ECS（Elastic Container Service）

AWSネイティブなフルマネージドのコンテナオーケストレーションサービスです。コンテナの実行環境としてEC2型（サーバー管理あり）またはFargate型（サーバーレス）を選択できます。

AWS Fargate — サーバーレスコンテナ実行

Fargateは、EC2インスタンスを管理することなくコンテナを実行できるサーバーレスコンピューティングエンジンです。ECSまたはEKSと組み合わせて使用します。

  • EC2インスタンスのプロビジョニング・パッチ・スケーリングが不要
  • コンテナに必要なCPU・メモリを指定するだけ
  • 使用したコンピュートリソース分のみ課金

Amazon EKS — Kubernetes管理サービス

Amazon EKS（Elastic Kubernetes Service）は、Kubernetesクラスターをフルマネージドで実行できるサービスです。オープンソースのKubernetesをAWS上で使いたい場合に使用します。

ECS vs EKS：ECSはAWSプロプライエタリ（AWSネイティブ、シンプル）。EKSはKubernetes標準（オープンソース互換、他クラウドとの移植性あり）。

🔶 試験のポイント（CLF・SAA 頻出）
  • Fargate = サーバーレスコンテナ実行（EC2インスタンス管理不要）
  • EKS = Kubernetes（k8s）のAWSマネージドサービス
  • ECS = AWSネイティブのコンテナオーケストレーション（ECSはFargateまたはEC2上で動作）
  • 「コンテナをサーバーレスで実行 → Fargate（ECSまたはEKSと組み合わせ）」
  • 「k8s標準を使いたい、他クラウドとの互換性 → EKS」
  • コンテナイメージは Amazon ECR（Elastic Container Registry）で管理
