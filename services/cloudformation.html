🏗 AWS CloudFormation CLF SAA

AWS CloudFormation は、Infrastructure as Code（IaC）を実現するサービスです。 JSON/YAML形式のテンプレートファイルを使ってAWSリソースを宣言的に定義・デプロイ・管理できます。 手動作業を減らし、インフラ構成の再現性と一貫性を確保します。

Infrastructure as Code（IaC）とは

❌ 手動管理の問題点
  • 人為的ミスが発生しやすい
  • 同じ構成を再現しにくい
  • 変更履歴が追いにくい
  • スケールアップ時に作業量が増大
✅ IaC（CloudFormation）のメリット
  • コードで定義 → Gitでバージョン管理可能
  • 同じテンプレートで複数環境（開発/本番）を再現
  • 変更の差分管理・ロールバックが容易
  • 自動化によりヒューマンエラー削減

テンプレートとスタック

📄 テンプレート（Template）

JSON/YAML形式でAWSリソースの構成を定義したファイル。「何を作るか」を記述する。

AWSTemplateFormatVersion: "2010-09-09" Resources: MyEC2Instance: Type: AWS::EC2::Instance Properties: ImageId: ami-xxxxxxxx InstanceType: t3.micro MyS3Bucket: Type: AWS::S3::Bucket
📦 スタック（Stack）

テンプレートをデプロイして作成されたAWSリソースの集合体。スタック単位でリソースを管理・削除できる。

例：「Webアプリスタック」＝EC2+ELB+RDS+VPCを一括管理

AWS CDK / AWS Service Catalog

💻 AWS CDK（Cloud Development Kit）

PythonやTypeScriptなどのプログラミング言語でインフラを定義できるフレームワーク。最終的にCloudFormationテンプレートに変換される。

開発者がコードでインフラを書きたい場合に使用

🛒 AWS Service Catalog

IT管理者が承認済みのCloudFormationテンプレートをカタログ（ポートフォリオ）として管理・提供するサービス。組織内のリソース作成を標準化。

開発者は承認された構成のみ使用できるよう制限できる

🔶 試験のポイント（CLF・SAA 頻出）
  • CloudFormation = IaC（Infrastructure as Code）の代表的サービス
  • テンプレート（JSON/YAML）→ スタックの流れを覚える
  • スタック削除で全リソースを一括削除できる
  • AWS CDK = プログラミング言語でインフラを定義（CloudFormationに変換）
  • 「同じ環境を複数リージョンに展開 → CloudFormationテンプレートを再利用」
  • 「インフラをGitで管理・バージョン管理 → IaC（CloudFormation）」
