🪣 Amazon S3 CLF SAA

Amazon S3（Simple Storage Service）は、インターネット経由でオブジェクト（ファイル）を保存・取得できるオブジェクトストレージサービスです。 高い耐久性（99.999999999%、イレブンナイン）と可用性を持ち、無制限のストレージ容量を提供します。 静的Webサイトのホスティング、バックアップ、データレイク、メディア配信など幅広い用途に使われます。

S3 の基本構造

🪣 バケット（Bucket）

オブジェクトを格納するコンテナ。グローバルに一意の名前が必要。バケット自体は特定のリージョンに作成される。

📄 オブジェクト（Object）

保存されるファイル本体（データ）とメタデータのセット。1オブジェクトの最大サイズは5TB。キー（ファイルパス）で識別。

ストレージクラス

ストレージクラス 可用性 最短保存期間 取得時間 用途
S3 Standard 99.99% なし 即時 頻繁にアクセスするデータ
S3 Standard-IA 99.9% 30日 即時 低頻度アクセス・長期バックアップ
S3 One Zone-IA 99.5%（単一AZ） 30日 即時 再作成可能なデータの低頻度アクセス
S3 Intelligent-Tiering 99.9% なし 即時 アクセスパターン不明なデータ（自動最適化）
S3 Glacier Instant Retrieval 99.9% 90日 即時（ミリ秒） 年1〜2回アクセスするアーカイブ
S3 Glacier Flexible Retrieval 99.99% 90日 数分〜数時間 長期アーカイブ（旧Glacier）
S3 Glacier Deep Archive 99.99% 180日 12〜48時間 最長期保存・最安値アーカイブ

Glacier 取得オプション

取得オプション取得時間コスト
迅速取得（Expedited）1〜5分最も高い
標準取得（Standard）3〜5時間中程度
大容量取得（Bulk）5〜12時間最も安い

ライフサイクルポリシー

オブジェクトの経過日数に応じてストレージクラスを自動的に移行したり、オブジェクトを削除したりするルールを設定できます。

典型的なライフサイクル例
作成後30日 → Standard-IA へ移行
作成後90日 → Glacier Flexible Retrieval へ移行
作成後365日 → 削除

バージョニング

🔄 バージョニングとは

同じキー（パス）のオブジェクトを上書きしても、過去のバージョンを全て保持する機能。

  • 誤削除・上書きからの復旧が可能
  • バケット単位で有効化
  • 一度有効化すると「無効化」はできない（中断のみ可）
🔐 MFA Delete

バージョニングが有効なバケットで、オブジェクトの完全削除にMFA（多要素認証）を必要とする設定。

  • 誤操作や不正アクセスによる削除を防止
  • バケット所有者のルートアカウントのみが設定可能

アクセス制御

🚫 パブリックアクセスブロック

バケットやオブジェクトを誤ってパブリック公開しないよう防ぐ設定。4つの設定項目があり、デフォルトでは全てブロックが有効。

静的Webサイトホスティングやパブリック公開には解除が必要。

📜 バケットポリシー

JSONで記述するバケット単位のアクセス制御ポリシー。特定のIPアドレスからのアクセス許可、クロスアカウントアクセスの設定などに使用。

👤 IAMポリシー

IAMユーザー・ロールに対してS3へのアクセス権限を付与するポリシー。同一AWSアカウント内のユーザー管理に使用。

📋 ACL（アクセスコントロールリスト）

バケット・オブジェクト単位の旧来のアクセス制御方式。現在は原則バケットポリシーが推奨。レガシー設定として残っている。

暗号化

🔒 SSE-S3（サーバーサイド暗号化 - S3管理キー）

AWSがキーを管理するサーバーサイド暗号化（AES-256）。設定が最も簡単。

🔑 SSE-KMS（KMS管理キー）

AWS KMSを使ってキーを管理する暗号化。キーの利用状況をCloudTrailで監査可能。

🗝 SSE-C（顧客提供キー）

顧客がキーを提供し、AWSはキーを保存しない暗号化方式。最もキー管理の制御が強い。

🏠 クライアントサイド暗号化（CSE）

ユーザーがS3にアップロードする前にデータを暗号化する方式。AWSはデータの復号に関与しない。

S3 Transfer Acceleration

CloudFront のエッジロケーション経由でS3へのアップロードを高速化する機能です。 地理的に離れた場所からの大容量ファイルアップロードに有効です。 エッジロケーションからAWSバックボーンネットワーク経由でS3へ転送するため、インターネット経由よりも高速・安定しています。

S3 Inventory

バケット内のオブジェクトの一覧とメタデータ（サイズ・最終更新日・ストレージクラス・暗号化状態など）を 定期的にCSV/ORC/Parquet形式で出力する機能です。 コンプライアンス・監査・コスト分析などに活用できます。

ストレージサービス比較（S3 / EBS / EFS）

比較項目 Amazon S3 Amazon EBS Amazon EFS
ストレージ種別 オブジェクト ブロック ファイル（NFS）
アクセス方法 HTTP/S（API） EC2にアタッチ EC2にマウント（NFS）
同時アクセス 無制限 原則1インスタンス 複数インスタンス
容量 無制限（自動） 最大16TB（手動拡張） 自動スケーリング
主な用途 静的ファイル保存・バックアップ・データレイク OSドライブ・DB 共有コンテンツ・Webファーム
🔶 試験のポイント（CLF・SAA 頻出）
  • S3の耐久性はイレブンナイン（99.999999999%） — 数字が問われることがある
  • Standard-IA と One Zone-IA には最短30日の保存期間がある（それより前に削除すると課金）
  • Glacier の取得オプション：迅速（1〜5分）・標準（3〜5時間）・大容量（5〜12時間）
  • MFA Delete はバージョニング有効時のみ設定可能、ルートアカウントのみ設定可能
  • パブリックアクセスブロックはデフォルト有効 → 静的Webサイトには解除が必要
  • 暗号化の種類と誰がキーを管理するかはSAAで頻出
  • Transfer Acceleration はCloudFrontエッジ経由でアップロードを高速化
  • 「コスト最適化 → ライフサイクルポリシーでGlacierへ自動移行」
  • S3はオブジェクトストレージ、EBSはブロック（OSに直結）、EFSはファイル共有
