✨ Amazon Aurora SAA

Amazon Aurora は、AWSが独自設計したMySQL/PostgreSQL互換のリレーショナルデータベースエンジンです。 RDSのエンジンの一つですが、通常のRDSと比べて大幅に高いパフォーマンスと可用性を実現しています。

Auroraのアーキテクチャ

Auroraの最大の特徴：データベースインスタンスとストレージが分離されたアーキテクチャ。ストレージは3つのAZにわたって6コピーが自動的に管理されます。

高可用性と自動フェイルオーバー

🔢 3AZに6コピー

ストレージは自動的に3つのAZに分散して6コピーを保持。2コピーが失われても読み取り可能、3コピーが失われても書き込み可能。

⚡ 自動フェイルオーバー（30秒以内）

プライマリインスタンスに障害が発生すると、AuroraレプリカがRDSマルチAZより高速に自動でプライマリに昇格します。

📊 最大15個のAuroraレプリカ

読み取り専用のAuroraレプリカを最大15個配置でき、読み取りトラフィックを分散できます（RDSは最大5個）。

📦 ストレージ自動スケーリング

ストレージは使用量に応じて自動的に拡張。最大128TB まで。容量を事前に指定する必要がありません。

Aurora Serverless

Aurora Serverlessは、アプリケーションの要求に応じてDBのキャパシティを自動的にスケールアップ・ダウンするオプションです。

  • DBインスタンスのプロビジョニングや管理が不要
  • 使用した分のみ課金（アイドル時は最小限のコスト）
  • 負荷が予測しにくいアプリケーションに最適
  • 開発・テスト環境、バースト性の高いアプリに向いている
🧭 どちらを選ぶ？ — RDS vs Aurora

🗃 Amazon RDS（非Aurora）

Oracle・SQL Server・IBM Db2が必要
既存DBエンジンをそのまま移行
MySQL/PostgreSQL標準互換で十分
コスト重視（AuroraはRDSより高め）
Oracle SQL Server コスト重視
VS

✨ Amazon Aurora

MySQL/PostgreSQL互換で高パフォーマンスが必要
最大15個の読み取りレプリカが必要
99.99%の高可用性が求められる
ストレージ自動スケーリングが必要
Aurora Serverless（可変負荷）を使いたい
高可用性 高パフォーマンス 最大15レプリカ
🔶 試験のポイント（SAA 頻出）
  • MySQL/PostgreSQL互換でRDSより高パフォーマンス（最大5倍）
  • 3AZに6コピーで高耐久性（RDSは2AZに2コピー）
  • Auroraレプリカは最大15個（RDS読み取りレプリカは最大5個）
  • フェイルオーバーはRDSマルチAZより高速（30秒以内）
  • Aurora Serverless = DBキャパシティ自動スケーリング、使用分のみ課金
  • 「読み取りトラフィックが多い → Auroraレプリカで分散」
  • AuroraはOracle・SQL Server・IBM Db2には非対応
