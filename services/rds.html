🗃 Amazon RDS CLF SAA

Amazon RDS（Relational Database Service）は、フルマネージド型のリレーショナルデータベースサービスです。AWSがバックアップ・パッチ適用・高可用性確保などを自動化するため、ユーザーはアプリケーション開発に集中できます。

RDS の主な特徴

🗄 対応エンジン（7種）
  • Aurora（AWS独自、MySQL/PostgreSQL互換・高性能）
  • MySQL
  • MariaDB
  • PostgreSQL
  • Oracle
  • Microsoft SQL Server
  • IBM Db2
⚙️ AWSが自動化する運用タスク
  • バックアップ・スナップショット取得
  • OSパッチ適用
  • ストレージの自動拡張
  • レプリケーション設定
  • メンテナンス（ダウンタイム最小）

高可用性：マルチAZ構成

マルチAZ構成では、異なる2つのAZにプライマリDBインスタンスとスタンバイDBインスタンスを1つずつ配置することで、可用性が向上します。スタンバイ側は常に同期レプリケーションされているため、フェイルオーバーが発生してもデータ損失が発生しません。また、フェイルオーバーは自動的に行われ、運用は継続できます。

マルチAZの重要ポイント：スタンバイDBインスタンスへのアクセスは読み取り専用も含めてできません（あくまで障害時の自動切替専用）。

パフォーマンス：リードレプリカ（RR）

リードレプリカは読み取り専用の非同期レプリカです。SELECT（読み取り）トラフィックをリードレプリカに分散させ、プライマリDBの負荷を軽減します。異なるAZや異なるリージョンにも配置可能です。

比較項目マルチAZ（スタンバイ）リードレプリカ
目的高可用性（HA）読み取り性能向上
レプリケーション同期（常に最新）非同期（若干遅れる）
読み取りアクセス不可（フェイルオーバー専用）可（SELECT専用）
フェイルオーバー自動（DNS切替）手動で昇格
クロスリージョン同一リージョン内可能

セキュリティ

🔒 ネットワークアクセス制御

基本的にRDSはVPC内からの接続のみ許可。EC2からアクセスする場合は、RDS専用のセキュリティグループを作成し、EC2からのアクセスを許可するルールを設定して接続します。

🔐 データ暗号化

DBインスタンスはAWS KMSと連携して暗号化できます。バックアップ・スナップショット・ログ・リードレプリカにも暗号化が適用されます。暗号化の設定は作成時のみ指定可能（後から変更不可）。

🔶 試験のポイント（CLF・SAA 頻出）
  • マルチAZはHA（高可用性）目的、リードレプリカはパフォーマンス（読み取り）目的
  • マルチAZのスタンバイには読み取りアクセス不可 — リードレプリカとの違いを混同しない
  • フェイルオーバーは自動、リードレプリカの昇格は手動
  • 暗号化は作成時にのみ設定可能（後から有効化するにはスナップショットからコピー）
  • RDSはEC2インスタンスクラス変更でスケールアップ/ダウン可能（縦スケーリング）
  • EC2のゲストOSパッチはユーザー責任、RDSのDBパッチはAWS責任（責任共有モデル）
