🏛 Well-Architected Framework CLF SAA

AWS Well-Architected Framework は、AWSが推奨するクラウド設計・運用のベストプラクティス集です。 効率がよく、コストパフォーマンスが高く、安全で信頼できるクラウドシステムを設計・運用するための指針を提供します。 技術の進化やAWSサービスの変化に応じて継続的に更新されるため、システム実装後も定期的に内容と照らし合わせて見直すことが重要です。

構成要素

フレームワークは「一般的な設計原則」と、6本の柱から構成されます。

🛡 セキュリティ

データやシステムをリスクから保護する。

🔁 信頼性

障害を想定し、安定して動作し続ける設計にする。

⚡ パフォーマンス効率

要件に合わせてリソースを効率的に使用する。

💰 コスト最適化

不要なコストを排除し、投資利益率を最大化する。

🛠 運用上の優秀性

運用を継続的に改善し、ビジネス価値を提供する。

🌱 持続可能性

環境負荷を抑え、サステナブルにワークロードを運用する。

一般的な設計原則

フレームワーク全体の基盤となる、クラウドネイティブな設計思想です。AWSだけでなくクラウド全般に適用できます。

  • キャパシティーニーズの推測が不要 — 負荷に合わせてリソースを自動でスケールアウト／スケールインし、過剰投資や容量不足を回避する。
  • 本番規模でシステムをテストする — 本番相当のテスト環境を一時的に作成し、完了後に破棄できる。
  • 自動化でアーキテクチャの実験を容易にする — 環境の作成・複製を自動化し、安全に何度でも実験する。
  • 発展するアーキテクチャを許容する — 設計時点で固定せず、ニーズや技術の進化に応じて継続的に改善する。
  • データに基づいてアーキテクチャを駆動する — メトリクスを収集し、データに基づいて意思決定する。
  • ゲームデーを利用して改善する — 障害を意図的に再現する対応訓練（ゲームデー）で、改善点の発見と運用者の経験を積む。
